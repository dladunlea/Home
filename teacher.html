2. Publishing access

This is what lets "Publish" save your changes straight to your live site. Your GitHub token is encrypted with a PIN you choose and kept only in this browser — never sent anywhere except directly to GitHub, and never sent or stored anywhere in plain text.

First time? How to get a token (2 minutes)
  1. Go to github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Give it a name like "Class site publishing" and set an expiration (e.g. 1 year — avoid "no expiration").
  3. Under "Repository access," choose Only select repositories and pick your class-site repo (e.g. Home).
  4. Under "Permissions," find Contents and set it to Read and write. Leave everything else as "No access."
  5. Click Generate, then copy the token (starts with github_pat_) — you'll paste it below along with a PIN of your choosing.

About the PIN: it encrypts the token in this browser's storage so a casual visitor to this page can't just open dev tools and read it out. It's a real deterrent, not bank-grade security — a longer PIN (6+ characters, letters allowed) is safer than a short numeric one. Don't share this page's link, and use "Lock now" when you step away from a shared computer.
